## 用户要求与已落地的代码

用户测试 v2 发现“永久”触发读取上限；要求换成独立分析文件，首次可能耗时须提示，创建和分析分开，不能点击入口就自动开始。同时希望入口与好友动态等同级并可自定义导航，并要人类说明、Jirai 指南及 Agent 交接。

已实现的主链：

```text
进入正常导航页面
  → 读取缓存元数据（不创建、不扫描）
  → 用户同意耗时提示并创建文件（仍不扫描）
  → 用户点击开始
  → 原生 SQLite 按 2,000 行分批整理源数据、提交进度
  → 按观察场次生成完整/未闭合在场片段
  → ready
  → 用户打开缓存，按人/分组/时间范围 SQL 查询与分页
```

支持暂停/续建、增量更新、确认后重建；账号及源路径隔离。旧分析文件重建时留备份。原始数据库只读，没有源 schema 迁移。

侧边栏集成已经改为 `navDefinitions` + `navLayoutDefaults` 的普通项目，默认排在下方，支持原有布局编辑。旧 `LocalInsightsNav` 顶部注入被移除。不要再改回 Header 插件形式，也不要误称新增了一个仪表板 widget。

## 数据正确性约定

时间统一 UTC 毫秒、范围 `[since, until)`。仅同一观察场次 / 精确实例 / 完整加入离开的重叠计时。重复证据不重复算，重复进入不承认不确定的前一个开始，缺失离开不补到 now，隐私状态不推测房间。

默认最大有效单段仍是 24 小时。这是片段可信度阈值，不是“永久”的查询跨度限制。

单人摘要可以看组外共同在场者；分组概览必须传 `groupOnly=true`，即使只有一个成员。一个人的组内配对应为零；点击这个成员后切换成个人摘要，才显示其全部同伴。

所有分页应从 SQLite 返回当前页而不是全表。显示五个页码不等于最多五页。相遇与日志都是 10 条预览、一次加 20 条，之后真分页；改变每页数量不能被监听器又重置回 10。

原有排除规则保持公开，仅限本分析功能。当前登录账号与配置排除账号不当作目标；这不意味着删除原版所有日志或使这些账号不可观察。

## 已知限制，不能改写成“已实现”

- 当前包面向 Windows x64 CEF。Electron/macOS/Linux 原生缓存桥接未完成验收。
- 没有完整 Jirai 迁移；说明入口见 `docs/JIRAI_GUIDE.md`。该指南不是功能实现承诺。
- 没有 CSV 导出，也没有文件管理器里双击 `.db` 自动打开程序的关联；在页面中打开当前账号的缓存。
- 初次分析未完成时不开放完整历史回顾；尚未做“先最近 30 天，边建旧历史边浏览”。
- 记录高水位 + 尾部回查不是普遍变更捕捉。旧时间的新 ID 会处理；对很早原行的修改、相同 count/max-ID 的文件替换可能识别不到。批量导入、替换和旧行改动后，应重建缓存。
- 当检测到已有历史表减少、ID 倒退或 schema 改变时，要求重建。当前好友表是可变化快照，不能用同一“历史删改”规则误判。
- 全局 GameLog 没有可靠的逐条历史登录账号字段。缓存目录隔离并不等于完全拆分过去不同账号产生的全局日志。
- 全年 / 多人组的 SQL 聚合仍可能耗时。批次内存受控不等于所有查询瞬间完成；组分析范围最多 200 人，超限明确报错，不丢弃成员。
