# VRCX Insights v3 验收指南

这是当前缓存版的测试清单。旧 v2 的演示入口、全量 JS 读取器和 5,000 / 50,000 行限制不是 v3 正常入口。不要拿旧截图或旧测试通过记录代替新版本验收。

## 测试前

从本仓库 Release 下载完整 Windows x64 包，记录 tag、提交 SHA、安装包 SHA256 和 `BUILD_INFO.json`。退出旧 Insights 并备份其独立配置目录；不要覆盖官方 VRCX 的配置。

正式账号的数据库只在自己的机器使用。公开复现报告用虚构 ID、名称与最小样本，不上传完整源数据库或新生成的个人分析缓存。

## 人工 UI 与持久化验收

| 场景 | 预期 |
| --- | --- |
| 首次进入共同游玩回顾 | 只显示缓存状态和耗时提示，不创建文件、不扫描历史 |
| 未勾选知情确认 | 创建按钮不可用 |
| 点击创建分析文件 | 文件和结构建立，状态为已创建；没有自动开始分析 |
| 点击开始首次分析 | 两阶段进度与处理数量更新，源库没有被分析模块迁移或修改 |
| 分析中暂停 | 当前批次结束后暂停，状态能恢复；不是把未完成结果当完整报告 |
| 分析中离开页面 | 不再发起新分析批次，重返页面后手动继续 |
| 退出并重新打开程序 | 可读取既有缓存状态，未完成的索引可继续 |
| 打开完成的回顾 | 不重新全量扫描源库 |
| 更新缓存 | 新增历史进入缓存，旧时长不重复累计 |
| 正常好友数减少 | 更新好友快照，不要求重建全部相遇历史 |
| 重建缓存 | 先明确确认；旧分析文件备份为 .previous；新文件仍等待手动开始 |
| 账号切换 | 上一账号的视图、候选名单、组内结果清除；新账号使用独立缓存 |
| 新数据库路径 | 使用新路径指纹对应的缓存，不复用另一文件的分析结果 |

本版暂停/续建并不表示“建到一半就能任意查询整段历史”。初建未完成时，完整回顾按钮不会把不完整数据展示为全部历史。首次先索引最近 30 天并同时浏览的能力没有实现。

## 导航验收

“共同游玩回顾”在正常侧边栏下部，与好友动态、游戏日志等共同使用同一布局管理。最上方新建仪表板区域不应再额外挂一个同名入口。

右键侧边栏打开自定义导航栏，移动、隐藏、恢复该项目；验证已有自定义文件夹、仪表板入口没有被重置。新功能是同级页面，不是新增一个仪表板 widget 类型。

## 数据与分页验收

选择一位已知有历史的玩家，验证 24h、7d、30d、自定义和永久。事件时间显示为本机时区，查询用 UTC 毫秒边界。包含状态/Bio 但没有完整房间配对的人也应能显示日志，不应凭空产生共同游玩时长。

相遇记录首屏 10 条，展开一次变 30 条，然后翻页；直接选择每页 20 条时必须真正显示 20 条，不能又被监听器重置为 10 条。超过 5 页的记录仍可翻到第 6 页和末页。相遇与日志的分页状态相互独立。

日志位于左列相遇记录下方。验证全部、进入、退出、状态、Bio 筛选以及改动前后文本。缺失可选来源表时，在诊断中说明缺失，不将它误写为“这个人从未修改过资料”。

创建两人组、多人组、一人组；分组概览只显示组内配对。一人组应没有组内配对。点击成员后查看其个人同伴，返回时恢复组内模式。编辑名称、增删成员、删除组，并重启确认保存。原 v2 分组应继续读取，超过 200 人的旧组不能静默截断。

针对自己的脱敏副本，测试新增记录、较旧时间的新导入记录、数据库替换和历史删改。新 ID 的旧时间记录会触发相应历史重放；较早原行直接修改、文件替换或批量迁移后手动重建更可靠，不能声称所有变更都会被自动识别。

## 统计边界

只有相同观察场次、精确实例地址、完整且正时长的加入/离开配对才计时。缺少离开、重复进入、观察者切换世界、隐藏位置不应推导出不存在的在场时间。单段超过 24 小时的安全阈值仍保留不计时处理。用户/房主关系不从这些证据中推测。

当前账号和继承的配置排除账号不参与新增分析。此规则不能让账号在整个 VRCX、其他客户端或其他人的电脑中不可见。

## 自动化命令

工具版本以 `package-lock.json` 和 GitHub Actions 为准；当前 Windows 发布链使用 Node 24、.NET 10 SDK。

```text
node build-scripts/apply-local-insights.mjs
node build-scripts/apply-local-insights.mjs
node --test tests/local-insights/analytics.test.mjs tests/local-insights/reader.test.mjs tests/local-insights/cache-integration.test.mjs
node tests/local-insights/run-report.mjs
npm ci
npx vitest run --config tests/local-insights/vitest.config.mjs
npm run prod
dotnet run --project tests/InsightsCache.Edges/InsightsCache.Edges.csproj -c Release
dotnet run --project tests/InsightsCache.Native/InsightsCache.Native.csproj -c Release -- --stress
```

第二次集成脚本运行不得产生额外源代码变化。原生测试是真实 SQLite 临时文件，不是模拟 SELECT 返回值；数据全部虚构。

大样本默认 6,001 场，压力模式 26,001 场、520,020 条加入/离开记录，加位置和其他事件。测试真实行数、时间交集、重复更新幂等、暂停重开、旧时间新增、源文件 SHA256 不变、缓存查询不依赖源库在线、翻到第 6 页等。边界测试单独覆盖重复证据、未闭合片段、好友快照变化、单人组和较晚导入的观察场次边界。

前端测试使用真实 Vue 组件与客户端代码，但原生桥接返回值模拟；这不能替代真实 CEF 页面验收。完整 Windows build 才会编译 `SQLiteInsightsBridge.cs`。

## 安装 / 并存 / 卸载

在独立环境记录官方目录、快捷方式、卸载项及配置备份。安装 Insights 后检查 EXE、数据目录、启动项、IPC/overlay 和卸载入口独立；官方协议处理器及官方配置不被替换。验证升级 v2 到 v3 后能识别版本，新缓存单独生成，旧偏好分组仍保留。

分别测试程序退出、重启、系统通知、VR overlay 和卸载后官方程序是否仍能启动。本次自动编译与安装器生成不自动证明上述真实桌面操作全部通过。

## 报告格式

输出 `LOCAL_QA_REPORT.md`：准确 tag/SHA、Windows/缩放/主题、执行命令、退出码、预期/实际、脱敏截图和 PASS / FAIL / NOT_RUN。只有自己执行过的步骤写 PASS。先报告数据错误/源文件风险/崩溃，再报告界面问题。

发布构建附带原生测试 JSON、Vue JSON、集成 diff、BUILD_INFO 和校验和。不要将构建运行中的中间状态当成已发布版本，也不要绕过失败测试。
